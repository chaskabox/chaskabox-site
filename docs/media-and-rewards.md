# Secure media and paused rewards

Uploads use the same operation ledger for product photos, payment QR images and brand logos/heroes. Pages admits a bounded multipart body and actual JPEG/PNG/WebP/AVIF signature; a private service-only Worker uses the native Images binding to decode pixels and create a single WebP frame for photos. Payment QR uploads are owner-only PNGs, decoded and re-encoded as PNG without resizing, at most 1024px per axis. This preserves QR pixels instead of applying lossy photo compression. Input is at most 5MB, 4096px per axis and 4 million pixels. Output is at most 1024px per axis and 2MB. SVG, GIF, corrupt data and declared MIME mismatches are rejected. Native PNG decode is tested; bank-app scanning is a separate owner acceptance check.

Production prerequisites: deploy the companion chaskabox-media-transform Worker with its switch off; bind Pages MEDIA_TRANSFORM to that Worker before the single final Pages deployment. Verify the account's free Images allowance and other account consumers. Keep Pages/Worker MEDIA_TRANSFORM_ENABLED and database media_upload_enabled off until isolated acceptance. The application monthly admission cap defaults to 1000 and cannot exceed 1000. Every reserved attempt counts; this is a conservative application limit, not Cloudflare account billing measurement. No Images hosting subscription, external image URL fetch, public Worker route or automatic paid upgrade is required by this code.

## External action recovery

A private operation with a server-created UUID/path is committed before processing/storage. Media registration, operation completion and media.uploaded audit commit together. On an ambiguous registration response, abort first locks and checks the operation: a registered asset is returned as success; an unregistered operation is fenced as aborting before cleanup. Unknown abort outcomes never delete the object. Failed/unknown cleanup remains visible to owner/manager under /api/admin/media/operations. Recovery only accepts an operation UUID and explicit confirmation; it never accepts an object path. Upload recovery waits at least 15 minutes before treating another request as abandoned. Storage deletion uses DELETE /storage/v1/object/{bucket} with JSON prefixes. Remote-storage convergence still requires isolated verification.

Deletion reserves under CMS then media locks, checks products/OG, brands, categories, homepage live/draft, theme, site settings, navigation and product history references, and atomically marks deleting plus audit before touching Storage. Relevant reference writes acquire the same media fence. Successful deletion leaves a tombstone; subsequent assignments of that path fail. Unknown deletion remains pending and resumes the same operation. Product history is deliberately protective; deleting a photo used in undo history requires an explicit history retention decision first. Legacy paths outside the owned UUID pattern require separate owner review.

## Inspected uploaded assets

Ten visible, non-mismatched original PNG uploads have exact-source aliases to locally decoded WebP assets. Combined bytes: 15,378,877 -> 833,666 (94.6% smaller). A changed database image URL immediately bypasses the alias. No original Storage object or product quantity was edited. Hidden product 202 was inspected but is not promoted or copied into the visible catalogue. Product 186's observed photo says PACK OF 48 while the listing says Pack of 12: only that exact source/pack combination is withheld with Photo under review. Owner approval of the correct pack/photo is required. Fourteen other visible product paths have no file; no fake packaging was generated.

## Rewards

Loyalty, referrals, birthday rewards and push are explicitly unavailable. The server rewards-status response reports each as unavailable; loyalty mutations fail closed. Unsupported birthday/device/referral values are removed from local storage, referral query attribution is discarded without altering other query/hash values, and no permission prompt or placeholder OneSignal SDK is used. Local cart/reorder reminders remain local. A durable verified-user loyalty ledger, approved reward rules, server referral attribution, authenticated DOB and push consent/token management are not implemented or claimed. Dormant birthday/abandoned-cart notification templates remain inactive.

## Verification

npm test includes actual offline native Images decoding, malformed-image rejection, chunked body limits, private role grants, audit rollback, reference fencing, ambiguous registration recovery, failed cleanup, exact-source aliases and paused rewards. npm run build:media is a dry run. These tests do not prove production CPU limits, account quota, managed Storage lifecycle or native PostgreSQL concurrency; those remain final release gates.
